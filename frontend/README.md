# Черновой тестовый фронтенд

Простой интерфейс поверх готового API (`../server/`) — без сборки, без
фреймворков, без дизайна. Задача — проверить работу API руками: обычные
формы, списки, кнопки. Ошибки API показываются текстом на странице, а не
только в консоли браузера.

## Запуск

Бэкенд должен быть уже поднят (из `server/`):

```bash
npm run migrate
npm run seed
npm start
```

Затем сам фронтенд (из `frontend/`):

```bash
npm start
```

Откройте <http://localhost:5173>.

## Как это устроено

`server.js` — маленький dev-сервер без зависимостей: раздаёт статику из
`public/` и проксирует всё под `/api/*` на бэкенд (`http://localhost:3000`
по умолчанию, переопределяется переменной окружения `API_ORIGIN`; порт
самого фронтенда — `FRONTEND_PORT`, по умолчанию 5173).

Прокси, а не CORS-заголовки на бэкенде, — специально: браузер видит один
origin и для статики, и для API, поэтому сессионная cookie (`HttpOnly`,
`SameSite=Lax`, без `Secure` в деве) работает как есть, без единой правки
в `server/`.

## Страницы

- `index.html` — точка входа, тестовые аккаунты.
- `register.html`, `login.html` — регистрация и вход (плюс восстановление пароля).
- `catalog.html` — список услуг и мастеров.
- `availability.html` — свободное время мастера на дату.
- `booking.html` — создание записи.
- `account.html` — личный кабинет: мои записи, детали, перенос, отмена.
- `admin.html` — админ-панель: все записи, услуги/категории, мастера
  (услуги мастера, график, исключения, блокировки времени), пользователи и роли,
  профиль салона.

Каждая страница валидна сама по себе — поля можно заполнять и вручную
(не только переходами по ссылкам), это нужно для проверки граничных
случаев API напрямую.
