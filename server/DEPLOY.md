# Сборка и запуск в контейнере

Касается только `server/` (HTTP API). У `frontend/` и `web/` — свои
dev-серверы раздачи статики, сюда не входят.

## docker-compose.yml (Coolify и подобные панели)

В корне репозитория лежит `docker-compose.yml` — панель, которая умеет
читать docker-compose (Coolify — умеет), разворачивает сервис из него
без ручного заполнения настроек. Собирает образ по `server/Dockerfile`,
поднимает том `booking-data` на `/data` и пробрасывает порт 3000.
Секретов в нём нет: `SESSION_SECRET` и пароль администратора приложение
придумывает само при первом запуске (см. ниже) — специально, чтобы их не
нужно было ни задавать руками, ни хранить в файле, который лежит в
репозитории (даже закрытом — история хранит всё, а доступ к ней рано или
поздно получает кто-то ещё).

Ручной запуск (без панели) — тот же compose-файл из корня репозитория:

```bash
docker compose up -d --build
```

## Сборка образа вручную (без docker-compose)

Из папки `server/`:

```bash
docker build -t booking-service-backend .
```

## Постоянное хранилище для базы

Файл базы должен пережить пересборку образа, поэтому он живёт вне `/app`
(куда копируется код) — по умолчанию по пути `/data/database.sqlite`
(`Dockerfile`, `ENV DATABASE_FILE`). Эту папку нужно смонтировать как
отдельный том, иначе при каждой пересборке база будет создаваться заново
пустой. `docker-compose.yml` в корне уже монтирует туда именованный том
`booking-data` — Coolify создаёт и переиспользует его сам, путь на сервере
руками искать не нужно. Папку `/data` при первом запуске на чистом томе
создаёт сам процесс (`src/db/connection.js`), падать из-за её отсутствия
он не должен.

Ручной запуск через `docker run` (если не через compose):

```bash
docker run -d \
  -p 3000:3000 \
  -e NODE_ENV=production \
  -v /путь/на/сервере/booking-data:/data \
  --name booking-service-backend \
  booking-service-backend
```

Миграции применяются самим процессом при старте, до того как он начнёт
отвечать на запросы (`src/index.js`) — отдельно их запускать не нужно, в том
числе при первом запуске на пустом томе. Уже применённые повторно не
выполняются (таблица `schema_migrations`).

`npm run seed` (тестовые данные) в контейнере не запускается — и не должен:
`seed.js` сам отказывается работать при `NODE_ENV=production`.

## Секрет сессий и первый администратор — без ручной настройки

Оба значения приложение придумывает само при первом запуске на пустой базе
и сохраняет рядом с файлом базы, на том же томе `/data` — поэтому они
переживают перезапуск и пересборку контейнера, но никогда не попадают ни в
docker-compose.yml, ни в git:

- **`SESSION_SECRET`** (ключ подписи сессионных токенов) — сохраняется в
  `/data/.session_secret` (`src/config/env.js`). Если переменная окружения
  `SESSION_SECRET` всё же задана явно (например, при переносе на другой
  сервер, чтобы старые сессии продолжили работать) — используется она, а
  файл не трогается.
- **Администратор** — при первом старте, если в базе ещё нет ни одного
  пользователя с ролью `admin`, создаётся один: email — `ADMIN_EMAIL`
  (по умолчанию `admin@ton-salon.local`, не секрет, можно смело держать в
  compose-файле), пароль — случайный, сохраняется в
  `/data/admin-credentials.txt` (`src/db/ensureAdmin.js`). Прочитать его
  после деплоя: `docker compose logs backend` (пароль печатается один раз
  при создании) или `docker compose exec backend cat /data/admin-credentials.txt`.
  Смените пароль после первого входа.

## Настройки (переменные окружения)

### Не обязательно, но стоит проверить

| Переменная | Зачем |
|---|---|
| `NODE_ENV=production` | Отключает `seed.js`, скрывает `resetToken` из ответа API восстановления пароля (см. `server/README.md`, «Дальше по проекту») и переключает генерацию `SESSION_SECRET`/администратора в постоянный режим (файл на диске, а не только на память процесса). Уже прописано в `docker-compose.yml`. |
| Том на `/data` (или на путь из `DATABASE_FILE`, если он переопределён) | Не переменная окружения, а инфраструктурное условие — без него база (и секрет, и учётка администратора) не переживут пересборку образа. Уже настроено в `docker-compose.yml` (том `booking-data`). |

### Есть разумное значение по умолчанию — трогать только при необходимости

| Переменная | Значение по умолчанию | Когда менять |
|---|---|---|
| `DATABASE_FILE` | `/data/database.sqlite` (задано в `Dockerfile`) | Если том монтируется не в `/data`, а в другое место. |
| `PORT` | `3000` | Если порт внутри контейнера должен быть другим (снаружи в любом случае маппится через `-p`/`ports:`). |
| `SESSION_SECRET` | генерируется сам, см. выше | Если нужен конкретный секрет, а не сгенерированный. |
| `SESSION_TTL_DAYS` | `30` | Если нужен другой срок жизни сессии. |
| `PASSWORD_RESET_TTL_MINUTES` | `30` | Если нужен другой срок жизни токена восстановления пароля. |
| `ADMIN_EMAIL` | `admin@ton-salon.local` | Если хотите войти под своим адресом сразу, а не переименовывать администратора потом. |
| `ADMIN_PASSWORD` | генерируется сам, см. выше | Если нужен конкретный пароль, а не сгенерированный. |
