# Тон — сервис записи и управления заявками

Сервис онлайн-записи для салона красоты «Тон»: клиент выбирает услуги,
мастера, дату и время и создаёт запись; администратор ведёт каталог услуг
и мастеров и видит все записи. Бэкенд — самостоятельный HTTP API на
Node.js и SQLite, без единой внешней зависимости. Фронтенд — черновой
тестовый интерфейс поверх этого API (обычные формы и списки, без
дизайна — задача не показать интерфейс, а проверить работу API).

## Что внутри репозитория

| Папка | Что это |
|---|---|
| [`server/`](server/) | HTTP API: аутентификация, каталог, свободное время, бронирование, админ-панель. Node.js + встроенный `node:sqlite`, без фреймворков и npm-зависимостей. |
| [`frontend/`](frontend/) | Черновой тестовый фронтенд поверх API — обычные HTML-формы/таблицы, минимум стилей. |
| [`docs/`](docs/) | Проектные документы: паспорт продукта, карта переходов прототипа, схема БД. |
| [`Full style guide DC/`](Full%20style%20guide%20DC/) | Визуальный прототип экранов (дизайн-канвасы) — справочник по дизайну, к API не подключён и не редактируется. |

## Требования

- **Node.js ≥ 22.5.0** (нужен для встроенного модуля `node:sqlite`), рекомендуется актуальный LTS (24.x — на нём всё разрабатывалось и проверялось). Скачать: <https://nodejs.org/> (выбрать версию LTS). `npm` ставится вместе с Node.js — отдельно ставить не нужно.
- **git** — чтобы склонировать репозиторий. Скачать: <https://git-scm.com/downloads>.
- Больше ничего: ни Docker, ни отдельной СУБД (PostgreSQL/MySQL и т. п.), ни глобальных npm-пакетов — весь стек умещается в Node.js. Оба `package.json` в проекте (`server/`, `frontend/`) не содержат внешних зависимостей, `npm install` в них по факту ничего не скачивает.

Проверить версию Node.js:

```bash
node --version
```

Если ниже `22.5.0` — обновите Node.js: если версия окажется недостаточной, `npm run migrate` в `server/` сам откажется запускаться с понятным сообщением, что и почему обновить (без загадочного стектрейса).

## Быстрый старт

Понадобятся **два терминала одновременно** — один под бэкенд, другой под фронтенд; оба процесса должны быть запущены и работать параллельно.

**1. Склонировать репозиторий**

```bash
git clone https://github.com/albinakazartseva2215/My_BS.git booking-service
cd booking-service
```

**2. Терминал №1 — бэкенд** (из корня репозитория):

```bash
cd server
npm install
npm run migrate
npm run seed
npm start
```

Бэкенд поднимется на <http://localhost:3000>. `.env` создавать не обязательно — без него сервис использует безопасные дефолты для локальной разработки (случайный сессионный секрет на время процесса, файл БД в `server/data/`, порт 3000). Полный список переменных и их смысл — в [`server/.env.example`](server/.env.example); понадобится, только если нужно что-то переопределить (например, порт).

**3. Терминал №2 — фронтенд** (из корня репозитория, не закрывая терминал №1):

```bash
cd frontend
npm install
npm start
```

Фронтенд поднимется на <http://localhost:5173> и сам проксирует все запросы `/api/*` на бэкенд (`http://localhost:3000` по умолчанию) — поэтому в браузере всё выглядит как один origin и настраивать CORS не нужно. Подробнее — [`frontend/README.md`](frontend/README.md).

**4. Открыть в браузере**

<http://localhost:5173>

### Если что-то пошло не так

- **Порт занят** (3000 или 5173 уже используются чем-то другим) — переопределите: бэкенд слушает `PORT` (например, `PORT=3001 npm start` в `server/`), фронтенд — `FRONTEND_PORT` и `API_ORIGIN` (например, `FRONTEND_PORT=5174 API_ORIGIN=http://localhost:3001 npm start` в `frontend/`).
- **Начать с чистой базы** — из `server/`: `npm run db:reset` (удаляет файл БД и накатывает миграции заново), затем `npm run seed`.
- **`node:sqlite` не грузится / просит `--experimental-sqlite`** — значит версия Node.js ниже нужной или скрипт запущен напрямую через `node ...js`, а не через `npm run ...` (флаг уже прописан в `package.json`, но только для `npm run`-команд). Подробный разбор — [`server/README.md`](server/README.md), раздел 3.
- Фронтенд открывается, но при любом действии видна ошибка вида «Не удалось связаться с API» — значит бэкенд (терминал №1) не запущен или упал; проверьте его вывод в терминале.

## Известные ограничения (осознанные, не забытые)

- **Уведомлений вне личного кабинета нет** (e-mail/Telegram-интеграция не входит в MVP) — из-за этого восстановление пароля в `NODE_ENV=production` не работает целиком: токен сброса некуда передать пользователю. В разработке (`development`/`test`) токен возвращается прямо в ответе API, чтобы функцию можно было проверить. Подробности — `server/README.md`, раздел «Восстановление пароля».
- **Оплата только на месте** — онлайн-платежей и статусов оплаты в системе нет.
- **Один салон с несколькими мастерами**, не маркетплейс — мультитенантности нет.
- Фронтенд в `frontend/` — черновой, для проверки API, не финальный дизайн; финальный дизайн экранов клиентского сценария — в `Full style guide DC/`.
